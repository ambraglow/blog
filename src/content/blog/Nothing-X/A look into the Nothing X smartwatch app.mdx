Some time ago i decided to buy a smartwatch, mainly because i want to keep track of my health, plus it makes for a stylish accessory. While window-shopping on the interwebs, i found an auction on Aukro - basically the Czech Republic's analogue of eBay - for a **CMF Watch 3 Pro** by **[Nothing](https://us.nothing.tech/)**; the technical specs looked good enough, and i really like their design language, so i ended up placing a bid on it.

In the meanwhile, i did some additional research, and a few things caught my interest:
- An article from the Chinese slice of the internet mentions that the main processor is an Action-Tech/Semi ATS3089C[^1]. A bit more digging reveals that this line of SoCs is quite widely used by Chinese ODMs[^2], which i thought was curious. For those who are interested: the article also shows a teardown of the watch with a detailed list of parts, so i really recommend reading it using a translator plugin like [Kagi Translate](https://chromewebstore.google.com/detail/alblebhaoakdgapamjdifdfnaicpnklm).
- The watch features built-in dual-band GPS which is pretty nice to have.<br/> I'd love to find a way to integrate that into my photoshoots as a way to record location for every picture.
- Nothing advertises 13 hours of battery life, which means perfect balance for my ADHD brain. If i have to recharge it less often, It's more likely i'll remember to grab the watch while heading outside. I may forget it on the charger otherwise.

A few days later i ended up winning the auction, so yay - the watch is mine! 
It was quite cheap. So unless the Czech Post delivery guy decides to throw the package in the [Vltava](https://en.wikipedia.org/wiki/Vltava) river, or i receive a bag of bricks or something, i should have a pretty good deal for 35 Euros.

### A curious cat - is a happy cat
#### I am a simple woman: when i get my hands on new hardware, i need to **touch it** or i'll explode.<br/>
In saner terms, i always get the urge to take apart devices i own, especially if it's something new and interesting. Unfortunately, satisfying my curiosity has resulted in a few cases where i lost the subject, which is how i learned to go for the less nuclear option first if possible. <br/>
And luckily, just a few days after my purchase, the perfect occasion for a firmware dump popped up! Nothing released a software update: Version 1.0.77.<br/>
A great way to satisfy my MacGyver cravings without disassembling the watch, which would consequently lose its IP rating.

I must say the changelog is very informative and detailed, describing the changes as - "Enhanced overall user experience" - and... that's it? Seriously? What? Why!? Would it really hurt them to be a bit more detailed?

<p style="font-size: 12px; text-align: left; font-style: italic; margin-top: 0px;">ngl, this was probably written by an LLM held at gunpoint, considering the preceding text that reads: "A new update is here with enhancements and fixes. Here's what's new in this update:".</p>

Anyway, this means i finally have an occasion to tinker with my watch. By grabbing the firmware update i could definitely find out more about it. Ultimately, I started figuring out a plan so i decided to delay the update for a while.

### Packet capture in progress...
At first i tried what worked for me in the past.<br/>
I previously owned a Samsung Fit 3, and at the time i used [PCAPDroid](https://github.com/emanuele-f/pcapdroid) on my phone to capture traffic and analyze it.
Samsung sent their firmware update through a non-encrypted connection using HTTP, which allowed me to simply recover the image from the capture.
But in this case, Nothing's API sends all data encapsulated in HTTPS, rendering it useless.

For my second attempt, i tried running PCAPDroid's MITM[^3] server. In the backend this runs the [mitmproxy](https://github.com/mitmproxy/mitmproxy) service. 

<p style="font-size: 12px; text-align: left; font-style: italic; margin-top: 0px; padding-top: 0px;">As a small side note, you're required to install <a href="https://docs.mitmproxy.org/stable/concepts/certificates/">their CA certificate for it to work.</a></p>

This method also didn't work; Nothing's app probably detected either that the certificate or the proxy was running and reported a network error when refreshing the firmware update page.

All that was left was to look into the app.

<p style="font-size: 12px; text-align: left; font-style: italic; margin-top: 0px;">Another side note for anyone looking into pcapdroid, here's something from their readme: "For rooted devices, the [pcapd daemon](https://github.com/emanuele-f/PCAPdroid/tree/master/app/src/main/jni/pcapd) can be directly integrated into your APK to capture network packets."</p>

### Disassembling in JADX
My next tool of choice was [JADX](https://github.com/skylot/jadx), although i'll admit i was quite lost here, i haven't done any significant amounts of software reverse engineering to know my way around decompiled classes, structs and code.
I'd rank the experience above looking at MacOS applications in IDA though.<br/>

My first instinct was to look for strings or classes that mention relevant keywords: such as *"OTA"*, *"frmware"*, *"update"*, etc.
This kind of led me to an interesting find: 
	Nothing has codenames for their watches and earbuds in their codebase, just like their smartphones, although this was ultimately useless for my research.

I'll admit i may have ADHD, which led me to laser-focus on these names for a good part of the search, and burning really quickly through my motivation to continue.
Thankfully, a painfully long while later, when [Kate](https://localcc.cc/) pointed out that what i was doing was stupid and gave me some directions, i was able to get back on track.

This is when i decided i was going to try a more practical approach and hook methods in the app with [Frida](https://frida.re/), a pretty nifty tool for reverse engineering, which supports scripting.
Using Frida is pretty easy, all i had to do was install the server service on my phone following [the guide on their website](https://frida.re/docs/android/).
I unfortunately fell into the javascript scripting hellhole soon after, i despise every second i had to write js. 
I used LLMs to aid me in writing a few drafts, then picked bits and pieces here and there that became my final script.
A lot of the reversing involved going through network-request related code, hooking and hoping something will print when running the app.

The process looked a bit like this:
1. Find a function or class that looks promising.
2. Modify my script to hook one of its methods, and print a simple "program passed through here" message.
3. Repeat.

After a good bit of repeating the process, i ended up settling on `com.nothing.log.Logger`, as evidence points to it being responsible for logging across the app.

This class has a few interesting methods:

Hooking onto `isCanLogger` and returning true for every call would enable a basic level of prints in log files. Of course, this is disabled by default.<br/>
I also figured out how to enable printing via `adb logcat`; performing the same trick on `isDebug` is what did it. Looking at this common snippet of code is how i deduced this:

```java
if (logger.isCanLogger(true)) {  
	String str = " " + tab.get() + StringUtils.SPACE + level.get();  
	String str2 = str;
	if (str2 != null && str2.length() != 0) {  
		Pair<String, String> trace = logger.getTrace(depth);  
		String strComponent1 = trace.component1();  
		String strComponent2 = trace.component2();  
		FileLog fileLog = FileLog.INSTANCE;  
		String str3 = logger.getSdf().format(new Date());  
		Intrinsics.checkNotNullExpressionValue(str3, "format(...)");  
		FileLog.print$default(fileLog, 4, str3, tag, str + StringUtils.SPACE + strComponent2, null, 16, null);  
		if (logger.isDebug()) {  
			Log.i(tag + strComponent1, str + StringUtils.SPACE + strComponent2);  
		}  
	}  
}
```
Yet another thing to note: any log report includes arguments and return values - and this is quite useful for me! It could mean that the OTA update URL ends up right in the logs.

### `Data: { "success": true }`

The final Frida script has a bunch of extra methods i didn't use; the useful ones are called with `setImmediate` at the end of the file, and they are as follows:

```javascript
function dumpNetworkLoadRepoFields() {
    Java.perform(function () {        
        
	var NetworkLoadRepo = Java.use("com.nothing.network.core.load.NetworkLoadRepo");
		console.log("[NetworkLoadRepo] INSTANCE: " + NetworkLoadRepo.INSTANCE.value);
		console.log("[NetworkLoadRepo] retrofit: " + NetworkLoadRepo.retrofit.value);
		console.log("[NetworkLoadRepo] apiService: " + NetworkLoadRepo.apiService.value);
    });
}

function isLogger() {
    var Logger = Java.use("com.nothing.log.Logger");
    Logger["isCanLogger"].implementation = function (canWrite) {
        console.log(`Logger.isCanLogger was called: canWrite=${canWrite}`);
        return true;
    };
    Logger["isDebugEnabled"].implementation = function (canWrite) {
        console.log("Logger.isDebugEnabled was called");
        return true;
    };
}

setImmediate(isLogger);
setImmediate(dumpNetworkLoadRepoFields);
```
