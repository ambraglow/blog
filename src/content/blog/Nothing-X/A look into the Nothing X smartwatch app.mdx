Some time ago i decided to buy a smartwatch, mainly because i want to keep track of my health, plus it makes for a nice accessory. While window-shopping on the interwebs, i found an auction on Aukro - basically the Czech Republic's analogue of eBay - for a CMF watch 3 pro, the technical specs looked good enough.

A few things that caught my eye:
- i found out quite early from the Chinese slice of the internet that the main processor is an Action-Tech/Semi ATS3089C[^1].
- the watch has built-in dual-band GPS which is quite neat.
- Nothing advertises 13 hours of battery life.

Besides, i really like the aesthetics which was just one more reason to bid on it.

I ended up winning the auction so, yay - the watch is mine!

#### A curious cat - is a happy cat
I am a simple woman: i own new hardware, i need to **touch it** or i'll explode.
Put into more sane terms, i always want to try and hack and take apart (if possible) gadgets when i get my hands on them.
And just a few days after my purchase the perfect occasion for a firmware dump popped up! Nothing released a software update: Version 1.0.77. 
I must say the changelog is very informative and detailed, describing the changes as "Enhanced overall user experience" and... that's it? Seriously? what? why? would it really hurt them to be a bit more detailed?
<p style="font-size: 12px; text-align: left; font-style: italic; margin-top: 0px;">ngl, this was probably written by an LLM held at gunpoint, considering the preceding text that reads: "A new update is here with enhancements and fixes. Here's what's new in this update:".</p>
Anyway, this means i finally have an occasion to tinker with my watch, by grabbing the firmware update i could definitely find out more about it. So i started figuring out a plan and decided to postpone updating its firmware for a while.

#### Packet capture in progress...
I tried what worked for me in the past in a similar situation for a different smartwatch.
At the time i was hacking on a Samsung Fit 3, the method i used was to run [PCAPDroid](https://github.com/emanuele-f/pcapdroid) on my phone to capture traffic and analyze it later.
Samsung sent their firmware update through a non-encrypted connection (just HTTP) which allowed me to simply recover the image from the capture.
But in this case Nothing rightfully decided using HTTP is stupid, so this didn't work as the file goes through HTTPS and there's no way i'm decrypting that.

For my second attempt, i tried running PCAPDroid's MITM[^2] server, in the backend this runs the [mitmproxy](https://github.com/mitmproxy/mitmproxy) service and you're required to install their CA certificate for it to function. 

>little side note and for future reference: "For rooted devices, the [pcapd daemon](https://github.com/emanuele-f/PCAPdroid/tree/master/app/src/main/jni/pcapd) can be directly integrated into your APK to capture network packets."

This just didn't work, Nothing's app probably detected either the certificate or the proxy was running and reported a network error when refreshing the firmware update page.
All that was left was looking into the app.

#### Disassembling in JADX
My next tool of choice was [JADX](https://github.com/skylot/jadx), although i'll admit i was quite lost here, i haven't done any significant amounts of software reverse engineering to know my way around classes, structs and code, i'd rank the experience above looking at MacOS applications in IDA though.
My first instinct was to look for strings or classes that mention: "OTA", "firmware", "update", stuff like that. Searching for the second option produced a few interesting results, i found out Nothing names their watches and earbuds differently under the hood, just like the majority of smartphone devices. Now, i'll admit i may have ADHD which led me to laser focus on these names for a good part of the search and i kinda burned through my motivation initially.

When [Kate](https://localcc.cc/) pointed out what i was doing was stupid, and gave me some directions, i was able to get back on track. This is when i decided i was going to try a more practical approach and hook methods in the app with [Frida](https://frida.re/), a pretty nifty tool for reverse engineering, which supports scripting.
Using Frida is pretty easy, all i had to do was install the server service on my phone following [the guide on their website](https://frida.re/docs/android/).
I unfortunately fell into the javascript scripting hellhole soon after, i despise every second i had to write js. 
I used LLMs to aid me in writing a few drafts, then picked bits and pieces here and there that became my final script.
A lot of the reversing involved going through network request methods, hooking and hoping something will print when running the app.

The process looked a bit like this:
1. find a `function` or `class` that looks promising.
2. Write/Modify the script to hook it and print a simple "program passed through here" message.
3. repeat.

I had a good look around all of the classes that i could find and looked interesting.
I ended up settling on `com.nothing.log.Logger` as it's responsible for logging across the whole app.

Hooking onto `isCanLogger` and returning true for every call is what enabled me to view a basic level of prints in log files, this is disabled for the app's release version.
I also figured out how to enable printing to android system log by looking at how the method is called, hooking `isDebug` and performing the same trick is what did it.

```kotlin
if (logger.isCanLogger(true)) {  
	String str = " " + tab.get() + StringUtils.SPACE + level.get();  
	String str2 = str;  
	if (str2 != null && str2.length() != 0) {  
		Pair<String, String> trace = logger.getTrace(depth);  
		String strComponent1 = trace.component1();  
		String strComponent2 = trace.component2();  
		FileLog fileLog = FileLog.INSTANCE;  
		String str3 = logger.getSdf().format(new Date());  
		Intrinsics.checkNotNullExpressionValue(str3, "format(...)");  
		FileLog.print$default(fileLog, 4, str3, tag, str + StringUtils.SPACE + strComponent2, null, 16, null);  
		if (logger.isDebug()) {  
			Log.i(tag + strComponent1, str + StringUtils.SPACE + strComponent2);  
		}  
	}  
}
```

The reports include arguments and return values - this was perfect in my case! The OTA update URL was right in the logs, along with other interesting links.

The final Frida script i made has a bunch of extra methods i didn't use, the useful ones are called with `setImmediate` at the end of the file:

```javascript
function dumpNetworkLoadRepoFields() {
    Java.perform(function () {        
        
	var NetworkLoadRepo = Java.use("com.nothing.network.core.load.NetworkLoadRepo");
		console.log("[NetworkLoadRepo] INSTANCE: " + NetworkLoadRepo.INSTANCE.value);
		console.log("[NetworkLoadRepo] retrofit: " + NetworkLoadRepo.retrofit.value);
		console.log("[NetworkLoadRepo] apiService: " + NetworkLoadRepo.apiService.value);
    });
}

function isLogger() {
    var Logger = Java.use("com.nothing.log.Logger");
    Logger["isCanLogger"].implementation = function (canWrite) {
        console.log(`Logger.isCanLogger was called: canWrite=${canWrite}`);
        return true;
    };
    Logger["isDebugEnabled"].implementation = function (canWrite) {
        console.log("Logger.isDebugEnabled was called");
        return true;
    };
}

setImmediate(isLogger);
setImmediate(dumpNetworkLoadRepoFields);
```
